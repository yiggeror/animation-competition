## 已实际关闭的接入问题

11 组素材确实进入运行时，v1 不在完整片中。S18 复用母版与新图统一专用软法线后，先前回母版时明显的受光突变已消除；其他镜头共享六张旧资产未被替换。当前帧未见此前脸颊墨黑块。本轮没有发现必须重生的多手、断腕或捂嘴接触错误。

实际 AAC 匹配既有母带 115–118 秒，喷笑 F15 比计划琵琶事件晚约 24.663 ms。局部片段实测 −23.26 LUFS / −10.95 dBTP；不能拿三秒局部响度要求替代整片 −16 LUFS 目标。

## 仍影响连续观感的实际问题

| 位置（相对视频内容起点） | 发现与下一步 |
|---|---|
| F14→15，约 0.625 秒 | 张嘴同时换了头颈、肩领位置；人物审认为可读作喷笑，动作审仍指出明显换姿。原速自然度未获主观验收。 |
| F18–20→21，约 0.875 秒 | k05 离膝的手没有在当前镜框里可读地出现，F21 手直接到近口。新增 k05 图并未补上镜内抬手路径。这是最需要继续解决的动作缺口。 |
| F27–44，1.125–1.875 秒 | 原片两姿每三帧等时交替三轮，头、手和肩一起反复换轮廓。对照版减少一次峰值并延长中间停顿，仍不是连续补间。 |
| F54–62，2.250–2.625 秒 | 原 k11 眉形偏忧愁/窘迫。对照版改用已有 k08 笑态，F63 落回 k07 母版；忧眉已消失。 |

## 对照版做了什么

由同一场景代码按 `n/24` 重渲全部 72 帧，只在本地 HTTP 响应中替换 `timelineFrames`，未改 Opus 实现或仓库生效时间表。图、灯光、镜头、字幕保持相同；共同 F0 与原片的解码 RGB 平均绝对差为 0.625，存在重新编码差异，不声称像素相同。

[精确覆盖 JSON](comparison/x18_laugh.timeline_override.flip.json)、[渲染及依赖清单](comparison/render_manifest.json)、[成片 manifest](comparison/manifest.json)、[动作增量复审](comparison/motion_delta_review.md)、[音频增量复审](comparison/audio_delta_review.md)。独立复核确认原 AAC 142 包的载荷和时间戳、解码 PCM、72 帧视频 PTS 全部一致。肩抖峰值由三次减为两次，收尾忧眉消失，未见新增接触硬伤；F53→54、F62→63 仍是离散姿态切换。

**建议将这支对照与原片一起实播裁决，再决定采用哪张曝光表；它没有修复前段跳手，也不是动作通过版。** 如继续当前方案，应先让抬手中间动作在实际镜框内可见，保持现有已修好的法线和音轨，不以再添一张镜外姿势充当补齐。未排其他镜头批量生成。
