## 先看结论

1. **交付文件真实存在，与指定提交中的 M4A 逐字节一致。** 实际格式为 48 kHz、双声道、AAC-LC，容器标称时长准确为 30.000 秒。独立解码成功，没有解码错误、NaN/Inf 或满幅样点。
2. **不是满幅削波的问题。** 解码样点峰值为 −0.989 dBFS；FFmpeg 真峰值约 −1.0 dBTP，独立四倍过采样估计约 −0.984 dBFS。不能仅凭这些数字判断音色好坏。
3. **8-bit 段存在明确的波形直流/极低频偏置，值得在后续混音前处理。** 18.5–22.5 秒左声道样点均值 −0.10434，右声道 −0.00854。源码的 25% 占空比脉冲波未做零均值处理，与此现象一致。修正这一点可以保留合成风格，不涉及否定音色审美。
4. **笛子加花版第五小节为 2.25 拍，其他小节为 2 拍。** 它从第六小节开始比固定伴奏晚 125 ms。需要确认是否有意错拍；若意图是“同一旋律原拍位加花”，应从原长音中扣除加花时值。它不等于一定与下一段主旋律重叠。
5. **30 秒文件终点没有明显的大振幅硬截尾证据；29.5 秒另有一个局部收尾点需试听。** 文件最后一帧最大绝对值约 −68.8 dBFS。最后锣声干音则按代码在 29.5 秒定长截断，该点实测相邻样点跳变约 −41.5 dBFS。是否形成可闻点击/突兀，需要实际听音确认。

**审查边界：本次没有可用的实际听音输入，只完成文件、解码、波形测量和源码/谱面审查。没有评价“好听”、板胡/笛子是否逼真、情绪是否适合画面，也没有认定全片已配乐完成。未修改音频、源码或 GitHub，未运行作者的音乐生成脚本。**

## 3. 波形偏置：8-bit 段的可量化问题

各区间样点均值（满幅 = 1）：

| 区间 | 左声道均值 | 右声道均值 |
| --- | ---: | ---: |
| 2.5–10.5 s | −0.0000125 | +0.0000072 |
| 10.5–18.5 s | −0.0000040 | −0.0000010 |
| **18.5–22.5 s** | **−0.1043407** | **−0.0085446** |
| 22.5–26.5 s | −0.0104551 | −0.0001423 |
| 26.5–30 s | −0.0000276 | +0.0000231 |

- 偏置不是一个偶然样点：19–20、20–21、21–22 秒的左声道均值分别约 −0.10590、−0.10660、−0.10282。
- `inst.py:278–282` 的脉冲波在一个周期内取 +1/−1，`demo.py:52` 使用 `duty=0.25`。理想周期均值为 `2 × duty − 1 = −0.5`；过采样/降采样本身不会去掉这个直流项。
- `inst.py:285–297` 没有对该脉冲波做零均值/隔直处理；全混音之后也未见统一隔直/高通。两个独立随机混响通道的低频响应可能进一步造成左右偏置不同，当前只将其列为与代码一致的解释，未做重渲染因果验证。
- 这会占用波形余量，也可能给后续压限/拼接增加不必要的低频负担；不能据均值直接断言实际听到了噪声或失真。
- 建议后续版本在保持占空比音色的情况下做隔直/零均值处理，再重新测量电平和真峰值。本次未作修改。

## 4. 谱面与安排时序

以下是**从源码独立计算的排程**，不是通过听音分离各声部所得。BPM = 120，一拍 0.5 秒；伴奏每小节 2 拍 = 1 秒。

| 时间 | 代码排程 |
| --- | --- |
| 0–约 2.48 s | 板鼓加密，21 次起音，最后起音约 2.275 秒；小锣在 1.2、1.7、2.0 秒起音 |
| 2.5 s | “呛”起音，板胡进入主题 |
| 2.5–10.5 s | 原主题 8 小节、16 拍；扬琴伴奏与梆子 |
| 10.25 s | 小锣过门起音 |
| 10.5 s | 笛子加花版与琵琶轮指进入；伴奏仍按每小节 2 拍推进 |
| 15.625 s | 笛子第六小节起音；对应伴奏第六小节在 15.500 秒 |
| 18.360 s | 笛子末音按 `gap=0.015` 结束有效音符包络；其余混响/滤波尾音另计 |
| 18.5 s | 第三段启动，“呛”、8-bit 方波、三角波低音及电子节奏进入 |
| 18.5–22.5 s | 8-bit 方波演奏主题前四小节，旋律频率是原主题的两倍 |
| 22.5–26.5 s | 板胡接主题后四小节，三角波低音和节奏继续 |
| 23.25 / 24.25 / 25.75 / 26.0 s | 代码合成的 8-bit “汪”效果起音 |
| 26.5 s | 收束“呛”起音 |
| 29.5 s | 最后“呛”的 3 秒干音达到数组末端 |
| 30.0 s | 输出结束，保留了最后干音结束后的 0.5 秒混响 |

### 笛子时值差异

- `THEME_A` 小节拍数：`[2, 2, 2, 2, 2, 2, 2, 2]`，合计 16 拍 = 8.000 秒。
- `THEME_A_DIZI` 小节拍数：`[2, 2, 2, 2, 2.25, 2, 2, 2]`，合计 16.25 拍 = 8.125 秒。
- 原因见 `score.py:22`：第五小节新增 `6:0.125= 5:0.125=`，原有长音时值未相应扣减。
- 解析器在 `score.py:32` 去掉小节线，只累加拍数，不校验每小节长度。`demo.py:43` 又丢弃了笛子版总拍数，`demo.py:48` 仍用原主题的 16 拍决定下一段时间。
- 因而第五小节后部开始产生变化，第六至第八小节整体晚 0.25 拍 = 125 ms。
- 笛子最后主音从 17.625 秒开始，时长 0.735 秒，结束于 18.360 秒；下一段在 18.500 秒起，仍有 140 ms 间隔。原谱尾部休止吸收了一部分时间差，**不应声称笛子主音必然压到下一段**。
- 处理取决于创作意图：若故意错拍可以保留并明确；若要同拍位加花，可从该小节长音中匀出 0.25 拍，并为谱面加入拍数校验。尚未改动。

### 连音实现的小偏差

`score.py:53–54` 的 `=` 只补满“当前音”的长度，没有兑现末尾注释所称的“把前一个音补满”。进入一组连音的前音若无 `=`，笛子会先保留 15 ms 的 gap；这又大于 `inst.py:96` 的 10 ms 相接容差，因此仍会触发前音 release。第一组就出现在约 11.110–11.125 秒之间。它不影响大段时长，但“完全连音/不重新吐音”的说明与实现有差别；是否需要更改应结合实际试听。

## 5. 收束锣声的局部定长截断

- `inst.py:270–274` 的“呛”由 3 秒大锣、1.2 秒钹和 1.6 秒小锣组合。大锣的慢衰减分量最长时间常数为 2.4 秒，但没有末端淡出，数组到 3 秒即停止。
- 最后一击在 26.5 秒，所以干音在 29.5 秒停止；`inst.py:374–376` 的混响卷积又裁到整段 30 秒长度。
- 解码后 29.5 秒边界相邻样点最大差为 0.008406（−41.51 dBFS）。边界前 20 ms 最大相邻差约 −54.54 dBFS，边界后 20 ms 约 −57.47 dBFS；该边界有可量化的不连续。
- 29.4–29.5 秒 RMS 约 −32.26 dBFS；29.5–29.6 秒约 −44.17 dBFS，与干音结束后仅余混响的排程相符。
- 这与“30 秒总文件硬切”是两个不同位置的问题。建议在 29.5 秒附近实际试听，必要时为锣声源尾部加适当包络，或调整收束位置以留尾；不能在未听音时直接判成明显爆音。

## 6. 声部、声像与合成来源

### 声部与混音结构

- 七个混音总线：板胡、笛子、扬琴、打击乐、chip、电子节奏、琵琶；不是每件打击乐都有独立交付 stem。
- `demo.py:68–69` 的声像参数（−1 左，+1 右）：板胡 +0.15、笛子 −0.10、扬琴 −0.35、琵琶 +0.35、打击乐 +0.05、chip 0、电子节奏 0。
- 对应混音乘数：0.55、0.50、0.35、0.40、0.60、0.35、0.50。声部内部还各有归一化/演奏强度，所以这些乘数不能直接解释为最终听感音量比例。
- `inst.py:359–362` 使用等功率声像；所有总线随后进入同一套双声道卷积混响，名义 RT60 为 1.1 秒、wet = 0.22，再全曲峰值归一化至 0.89 后写出 WAV。
- `demo.py:28–29` 有一段计算 `tk` 但不使用的循环，属于无效代码，不会产生额外伴奏音符。实际扬琴后半拍起音按 0.25 / 0.75 秒安排。

### 对“本地代码合成”的可支持声明

在本次完整读取的 `audio/inst.py`、`audio/score.py`、`audio/demo.py` 中：

- 板胡、笛子使用振荡器/谐波、噪声、包络和滤波。
- 扬琴、琵琶使用噪声激励的 Karplus–Strong 类合成。
- 梆子、锣钹等使用衰减模态正弦和噪声。
- 8-bit 使用脉冲波、三角波及噪声；“汪”明确是合成声音设计，并非真实狗叫录音。
- 混响脉冲响应由本地随机数、滤波和衰减包络生成。
- 这三份文件没有读取外部音频样本、下载素材或调用远程生成 API 的路径；依赖为本地 Python、NumPy、SciPy 和同目录模块。

因此可以说：**“已审查的这套源码采用本地程序合成，未见加载外部采样。”** 不能扩展成“全项目没有第三方素材”“音频版权已全部清理”或“已证实成品一定由当前源码完整重建”；本次没有做这些证明。
