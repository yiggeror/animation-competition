# 《来电》S02 / S05 实际预览独立审片

审查对象：提交 `98983eceb957c75ae82a81d0f46a0a5840bc8a10` 的两支原始 MP4。只审这两镜，不代表全片、声音、相邻镜头或全仓版权已通过。

## 结论先行

- **S02 可保留**：横握手机、程序小游戏、可读的 2% 与充电闪电、按一下跳一次的基本节奏成立；画面和屏幕保持稳定共面，没有数字乱码、内容滑出屏幕或明显透视漂移。
- **S05 暂不按最终镜头放行**：最主要的问题是“狂按”未形成清楚的反复按下/抬起，尤其右拇指在近两秒的狂按段实际近乎长按。其次，现行剪辑顺序中 S04 已停电，S05 却又保留 0.5 秒充电闪电，并到 0.875 秒才出现 1%，需处理开头状态或明确这是对停电瞬间的剪辑重叠。
- **S05 熄屏的光暗因果可以保留**：屏幕变暗、周边蓝色溢光和拇指冷边一起消失，手和竹席显著变暗。正式剧本明确保留窗外月光，不能仅因黑屏后仍能看见手和竹席而判错。应修正“屏幕唯一光源”的过度表述；本审查不要求整帧变黑。

## 1. 核验范围与方法

- 两片均为 H.264、960×540、24 fps、96 帧、4.000 秒，均无音轨。
- 对原片逐帧解码，按顺序看完全部 192 帧 contact sheets；另查看全尺寸关键帧和状态栏、右拇指局部。
- 帧号采用 **F00–F95**；F00 = 0 秒，F95 = 3.958 秒。磁盘 `frame_001.png` 对应 F00，不是 F01。
- 原片 SHA-256 与固定提交中的 `renders/checkpoint2/s02_phone_preview.mp4`、`s05_phone_preview.mp4` blob 完全一致。因此此处实际观察和固定提交代码可对应。
- 只用 `git show 98983ec:…` 阅读 `js/code/phone.js`、`s02.js`、`s05.js`、`js/film/edl.js`、`docs/preproduction/script-v3.md` 等；未改变共享 clone。注意 EDL 的真实路径是 `js/film/edl.js`。
- 没有重渲片、改片、额外生图或任何 GitHub 写入。抽帧/拼排仅用于审片证据。

## 2. 实际画面观察

### S02：保留

1. **信息读得清。** 首帧就能读到 21:47、1280、2% 和充电闪电；2% 与闪电持续到结尾。推近后电量更醒目，游戏、手和机身仍保持一个平面。没有真实游戏名称、品牌标识或可见截图边缘。
2. **横握成立。** 两手支撑机身，两个拇指覆盖左右虚拟按键，充电线从横屏左端进入。持握姿态在镜内连贯，没有手指数量突然增减、脱离手机或明显穿插跳变。轮廓是简化平涂，不需要把这支镜头改成 AI 图。
3. **基本游戏节拍成立。** 约 0.45、1.35、2.20、3.05 秒各有一次右拇指按压及人物起跳，木箱左移、金币变化、分数增加；四次跳跃之间有回落。后半段推向电量时人物渐出构图，是取景引导，不是游戏突然消失。
4. **光照可读。** 日光灯下竹席和肤色亮，机身/手后有软阴影。没有把 S02 误渲成停电状态。

证据：`keyframes/s02_f00_0.000s.png`、`s02_f12_0.500s.png`、`s02_f39_1.625s.png`、`s02_f95_3.958s.png`；完整逐帧表在 `contact_sheets/s02_*`。

### S05：核心时序读得出，但开头与“狂按”需处理

| 实际帧 | 本镜时间 | 可见状态 |
|---|---:|---|
| F00–F11 | 0.000–0.458 s | 2% + 充电闪电；房间已经是暗态 |
| F12–F20 | 0.500–0.833 s | 闪电消失，仍是 2% |
| F21 起 | 0.875 s | 变为 1%，红/白交替闪烁，数字保持可读 |
| F27–F73 | 1.125–3.042 s | 拉开后持续游戏与晃动；右拇指大多贴住按键，缺少清楚的释放循环 |
| F74–F75 | 3.083–3.125 s | 游戏画面明显变暗，周围手/席也同步暗下去 |
| F76–F95 | 3.167–3.958 s | 游戏和状态栏消失，黑屏保留微弱玻璃反光；没有重新亮屏 |

**需处理 A：开头电力状态与现行 EDL。**

实际开头不是“1%→猛按→黑屏”，而是“2%仍充电→停止充电→1%→操作→黑屏”。单镜里这段变化清楚，问题是 EDL 顺序为 S02 → S03（6 秒）→ S04（8 秒，灯灭/电视灭/扇停/月光）→ S05。不能按 s05.js 注释把它当作直接承接 S02 结尾的连续时间。

最小下一步：保持现行 EDL 时，让 S05 开头已经无充电闪电，优先直接显示 1%；若必须保留闪电消失的细节，把该特写明确放在 S04 停电发生的当口，并在连剪中验证时间重叠。这里没有检查 S04 实际片，不能断言它的停电点精确在第几秒，也不能凭本镜证明连剪已经成立。

**需处理 B：狂按动作不够成立。**

全尺寸和逐帧局部可见：约 1.75–3.04 秒相机拉稳后，右拇指只小幅漂动，几乎一直压住；左拇指的左右摆动和手机颤动更明显。观众能读成“着急操作”，但很难读成“手指飞快、猛按”。这不是只看代码提出的猜测，证据见 `keyframes/s05_right_thumb_mash_crops.png`。

最小下一步：只缩短狂按的按下/回弹周期，使每次动作在 24 fps 下有可辨认的离屏帧和重新落下帧；优先修右拇指，再与左拇指错峰。无需重做手的整体造型、背景或游戏美术。

**可保留：熄屏与余光。**

- F73→F74→F76 的屏幕、手、席共同变暗，蓝色屏幕光范围收掉，拇指冷色亮边消失；没有“屏幕灭了，手仍保持亮屏照度”的现象。
- 黑屏后手掌/指甲/席纹仍可辨，亮度明显低于亮屏段。正式剧本第 2 场写有窗外月光落在竹席上，所以这属于允许的余光，不构成独立退修理由。
- 余光较均匀、没有单独画出窗形光斑，是否与 S04/S06 的月光方向严格匹配仍需连剪判断。当前两支片不足以宣布全片光位已闭环。
- 黑屏后右拇指还有两次轻戳，可读成“不甘心再试”。它们仍落在屏幕，不是清晰的机身电源键动作。若正式剧本“猛按电源键”必须逐项落地，应在 S05/S06 连剪中另核；本 EDL 对 S05 仅要求 1%、狂按、黑屏，不据此扩增本次返工。

## 4. 代码证据与推论（与实际片观察分开）

1. **狂按为什么变长按：** `s05.js:6–11` 将间隔约 0.11–0.17 秒的 MASH 交给 `thumbAt`；`phone.js:357–365` 的单次按压包络约长 0.34 秒，重叠时取最小 lift，所以后一次覆盖前一次释放。按实际 24 fps 时点计算，F27–F73 右侧 `pressed` 持续为 true；1.15–3.05 秒内采样 46 帧全部 pressed，lift 仅 0.25–0.405，没有完整回抬到 1。右按键视觉反馈也因此近乎持续按下。
2. **状态时间为什么如此：** `s05.js:13–15` 明写闪电到 0.47 秒才消失、0.85 秒才降到 1%、3.05 秒开始暗、3.13 秒完全熄灭。离散到 24 fps 后与上表 F12、F21、F74、F76 一致。
3. **余光来自哪里：** `phone.js:275–280` 有屏幕无关的月光底色和肤色底光；`300–304` 的蓝色溢光、`279` 的冷边都乘 screenOn。`334–338` 明写黑屏玻璃反射月光。实现本身是“月光 + 屏幕光”，不是屏幕唯一光源。应改说明口径，不能用唯一光源的宣传字面否定正式剧本允许的月光。
4. **游戏的次要节奏限制：** S05 每三个 MASH 才触发一次游戏跳跃，间隔约 0.40–0.43 秒，短于 0.55 秒的单跳时长；代码取重叠跳跃高度最大值，实际中段人物因此一直有些悬空。这不阻止读懂跑酷，优先级低于拇指动作；最小修复若触及 MASH，顺便保持游戏跳跃与可见按压相符即可。
5. **分数是局部重算。** `drawGame` 的分数从 1280 加“本镜 jumps 已触发数”计算，S05 拉开时可看到 1280，而 S02 之前已出现更高分数。若要明确同一局连续运行，可接续分数；这是次要连续性润色，不作为本次首要阻断。

## 5. 游戏素材来源的有限核验

- 本镜调用链只导入本仓库 `phone.js`。游戏天空、云、山、地面、箱子、金币、角色、按键、状态文字均由 Canvas 路径、填色和文字绘制。
- `drawImage` 在该模块仅用于本函数生成的竹席 OffscreenCanvas；未见游戏截图、第三方游戏贴图 URL、Image/fetch 图像加载入口。实际帧也未见已识别的真实游戏品牌或 UI 截图。
- 因而可以说：**这两镜已检查的游戏画面路径未使用外部游戏截图素材，程序自绘路线成立。** 不能据此宣称全仓素材、字体、音乐、参考设计或版权均已全面审核。`CREDITS.md` 的宽泛自述不是本结论的唯一依据。

## 6. 下一步与验收边界

1. 保留 S02 与 S05 已成立的横握、可读电量、熄屏因果、余光和整体构图。
2. 最小返工集中 S05：修右拇指按压包络；处理进入本镜时仍充电的状态/剪辑重叠。
3. 对改后的 S05 再看 24 fps 实际片：每次猛按是否有落/起，第一帧是否与 S04 停电状态一致，F74/F76 类的熄屏因果是否保留。
4. 只在与 S04、S06 连剪后判断月光方向、黑后按电源键以及同一局分数连续性。当前审查不放行全片，也不授权发布。
