## 当前压平重抠与旧问题不同

先前fff848b报告复现的是直接将透明PNG转RGB后抠背景，不能套用到你现在先垫(190,190,190)的流程。主审重新检测实际x18_f06：原alpha<16而新alpha>128只有4像素，旧直接转RGB流程为10116；原alpha>128变为<16有2436像素（旧直接RGB流程1129），仍需看边缘收缩与场景打光，不能只比数字。

原件alpha最常见253有450173像素、254有153711像素，内部接近不透明但并非255；你描述的半透明来源确实存在。当前资产alpha=255为660065像素，约占其alpha>128区域97.4%。附[实际统计](alpha_stats.json)。主审查看[头部原件左/当前处理右的暗灰合成](head_original_left_current_right_bg32.png)，头顶翘发在两张资产均存在，场景拼图中新图翘发不易见需另核打光；不能误记为生成时缺失。

所以我方fff848b保留alpha补丁仅作为保真候选，不要求你立即覆盖现在的压平处理。应以实际透明边缘和实渲结果决定。
