# S18 关键帧试点：合成器独立审查

结论：**现有代码具备按给定时间表逐张硬切、配准并接入 S18 打光的基本能力；当前不能验收为“12 张计划已按 24 fps 正确成片”，更不能验收动作自然。** 冻结时没有 `assets/flips/`、正式 flip JSON 或新角色序列，S18 实际会回退旧片。应先解决显式模式/错误、母版坐标系和整数帧时间表，再接入 k06 等实际新图。此次没有改仓库，没有生成角色，也没有制作冒充实际 S18 的探针影片。

## 需在正式试片前处理的事项

### 1. 静默旧片回退会掩盖加载失败

`s18.js:11` 对 `loadFlip` 的任何异常不记录原因，写入 `FLIP=null`。探针连续调用两次只尝试加载一次，两次均返回 null；补齐文件后在同一模块实例内也不会重试。缺 manifest、任一固有色缺失/解码失败、部分结构错误都会进入同一旧片路径。旧路径为前 0.42 秒 B 态、之后单张 `x18_laugh` 的整卡伸缩/倾斜；输出仍然可以正常长达 3 秒。

最小要求：本次试点采用明确 `required` 模式，加载失败时终止该试片并保留 URL/错误。旧片只在显式选择 legacy 时可用，不能用自动回退判断试点完成。交付 manifest 写出 `mode: flipbook`、实际采用的文件/哈希和每个输出帧的 key ID。法线/材质缺失的平图回退也要记入 manifest。另注意：坏 timeline/越界索引可能在 `frameAt/flipMaps` 阶段才报错，该部分不在此 catch 内，不能说所有错误都会安全回退。

### 2. 第一张自参照不等于母版坐标

实际资产尺寸：

| 文件 | 尺寸 | Alpha 非零包围盒 |
|---|---:|---|
| `assets/chars/x18_laugh.png` | 635×1175 RGBA | (19,16)–(613,1159) |
| 同名 `_n`、`_m` | 635×1175 RGBA | 同上 |
| `assets/chars/x16_arms_loose.png` | 635×1175 RGBA | 同上 |
| `collab/refs/anim_18_xiaoman_laugh_cover.png` | 1254×1254 RGB | 无 Alpha |
| `renders/keyframes/S18/k01…k12.png` | 635×1175 | 骨架说明图，不是可用角色帧 |
| 隔离运行 prep 后的旧 anim_18 三图 | 1254×1254 RGBA | (359,36)–(953,1179) |

`prep_flip.py:9–11` 保留输入整幅，不做归一化。`flipbook.js:18–27` 输出画布采用序列参考帧本身尺寸，参考帧自己的变换恒等；只把其他帧对齐到它。`s18.js:21–23` 无论新图尺寸如何仍使用 `RIG16` 的 `ox=144, oy=856, sc=13`。因此原生尺寸/裁切不一致会导致整组位置或尺度错误；两点配准无法自动识别并纠正第一张对母版的偏移。旧原图与母版的 Alpha 包围盒恰差 (340,20)，在当前固定放置参数下这不会自动被扣除。

可以采用的最小接口（建议，由 Opus 实现）：

```json
{
  "target": { "width": 635, "height": 1175, "anchors": [[0,0],[0,0]] },
  "fps": 24,
  "durationFrames": 72,
  "frames": [{ "file": "x18_f06", "sourceSize": [635,1175], "anchors": [[0,0],[0,0]] }],
  "timelineFrames": [[0,0]]
}
```

上例 `[0,0]` **仅为接口占位，不能作实际锚点**。target anchors 必须在正式 635×1175 母版上实测；每张 source anchors 对应同一对静止特征。所有帧，包括第一张，都映射到 target，而非第一张自定坐标。若已在外部统一到母版画幅且角色位置一致，可直接提交规范化图并保留 identity 变换。原件、规范化变换、规范化后尺寸/哈希应同时记录。

### 3. 时间表不是已经实现的“一拍三”

`frameAt` 是按起始秒数取最后一个 `t0≤t` 的项。它不插帧、不叠化、不自动重复 8/9，不强制 24 fps，也不限制输出总帧数；外部必须用 `n/24` 渲染 n=0…71。

当前没有 flip JSON。**若**直接把 `docs/keyframes/S18.json` 的 12 个 `t` 按序作为 timeline，实测结果是：

| key | 输出帧（从 0 计） | 停留帧数 |
|---|---|---:|
| 1 | 0–5 | 6 |
| 2 | 6–10 | 5 |
| 3 憋笑 | 11 | 1 |
| 4 喷笑 | 12–14 | 3 |
| 5 | 15–19 | 5 |
| 6 抬手中途 | 20–22 | 3 |
| 7 捂嘴 | 23–25 | 3 |
| 8 A | 26–28 | 3 |
| 9 B | 29–45 | 17 |
| 10 | 46–55 | 10 |
| 11 | 56–62 | 7 |
| 12 | 63–71 | 9 |

0.42 秒会在 F11=0.4583 秒才生效，0.50 秒已切 F12，故“憋笑”只有一帧。1.17 秒后 B 会停 17 帧，不会抖三次。应交整数帧曝光表，并显式填写复用项；例如维持原 A/B 起点、三循环可写 A@26、B@29、A@32、B@35、A@38、B@41，之后到 46 接 key10。此为可采用的时序建议，**尚未作为正式表获艺术验收**。憋笑是否延长至 3 帧、喷笑与声音如何对齐须明确选择，不能由小数近似偷偷决定。本审查没有试听。

文档“12 key / 11 张不同图”的表述也不充分：8、9 是两种不同肩位，可在时间线上复用这两张；复用次数本身并不把 12 个不同姿势自动减少为 11 张。应列明确文件到 key 的映射，最终用实际图核对。

## 配准、Alpha、头位置与光照

- 两点计算是相似变换（平移、旋转、等比缩放），不是可校正所有形变的任意仿射。浏览器探针用不同尺度和 -90° 转角的输入，两个锚点精确落到 (20,20)/(50,20)，参考矩阵为恒等。数学基本正确。
- 代码没有锚点间距、有限数、尺寸、reference index、timeline 单调/范围校验。重合锚点实测产生 6 个非有限矩阵项，Canvas 没有抛错；不能据“无异常”判断配准成功。应拒绝退化/过短锚线，并记录每帧角度/尺度和变换后 Alpha 是否越界。
- 领口中心与后脑不是本动作的不动点：计划含耸肩和头后仰。将它们强行配准会抵消预期动作，并使本来静止的下半身/凳子整体移动或缩放。宜从未动的凳子/下半身选有足够间距的可辨特征，再单独量头、脸、肩、腕是否按意图变化。骨架计划中的头中心 x=246.73…317.69，y=238.09…249.34（母版坐标），本就含约 71 px 横向意图变化；不能既要求这个计划又强锁头中心。见 `planned_head_motion.json`。
- S18 flip 分支在固定镜头下使用同一 billboard 矩阵，没有旧版整卡呼吸/倾斜叠加，这是合适的。它也不理解“头”或“手”：所有身份、表情、局部大小和动作质量来自图片本身。两点一致不保证这些部位一致。
- Alpha 贯穿三张图；真实旧原图隔离 prep 后三张 Alpha 逐像素相同，灰底主体抠出成立。缺 `_n/_m` 时，浏览器探针证实用固有色 Alpha 做 `source-in`，图外透明、图内为平法线/普通材质，不会自动填满整张矩形。该结论限此旧图和合成探针，不能替代新图的发丝、手指缝、白领、灰影检查。cutout 会删除某些与灰底近色的封闭区域并做形态学收边；新图若背景/轮廓变化，仍可能误蚀或残灰。
- 已存在但尺寸错误的法线/材质图不会被验证。探针用 160×100 固有色配 8×8 法线，在角色内测到固有色 Alpha255、法线 Alpha0；最终 shader 以法线 Alpha 判断卡片覆盖，足以造成部分人物消失。生产接入须检查三图尺寸与 Alpha 一致。
- 配准会转动法线图像的位置，但没有转动 RGB 编码的 XY 法线向量。-90° 探针的非平法线仍为原 RGB(218,128,218)。小幅校正且 card_soft 法线很浅时影响可能小，但不能视为严格一致光照。若允许明显旋转，需旋转法线向量或在配准后的 Alpha 上重新生成柔和法线；否则将校正角限制在很小范围并以实际打光图验收。
- 配准画布固定为 reference/target 尺寸，变换后的发梢/手/鞋超出边界会被裁掉；当前未报警。不能靠放大/旋转“对上头”而不检查全身边界。

## 本轮可给的通过范围

通过的是：冻结合成器在合成输入上可正确执行两点相似变换、透明 Alpha、缓存和 72 次时间采样；隔离预处理对真实旧图可执行，三图尺寸/Alpha一致。

尚未通过的是：12 张新图是否存在且身份一致、k06→k07 抬手/捂嘴是否成立、头/手/衣服是否闪变、实际 960×540 灯光和跨镜接点、修正曝光表后的节奏及正常速度自然表演。此次没有正式新序列可渲，没有正常速度视觉播放输入；不能把一拍三、逐帧无报错、72 帧数量或骨长相同等同“好看”。首张 k06 与复用母版 k07 可先小范围接入验证，不能据此宣称 12 key 全段完成。
