**两张实际 922×1706 原件目前不能直接接入：正常分辨率缩小被当成角色形变拒绝。整数帧采样问题已修复；新图尚未形成正式可验收影片。** 本轮不改仓库，旧 patch 仅作历史备选。

冻结 HEAD `560e2617d374f13b3d3021f7777fc11a82c4d916`；flipbook SHA256 `e71568a0dd8c0013cc7b51299db9260d8f508e836a559f61a06652ae618d7a13`。五份冻结源码、两原件路径/尺寸/哈希和所引用的实测点在 `source_manifest.json`。浏览器复现命令：`node probe.cjs`；结果 `probe_results.json`。采用 systematic-debugging 先复现，并按 verification-before-completion 核查结果。

## 1. 真实输入被缩放限制拒绝

Chromium 实际解码 k06 v1、v2 原件，均为 922×1706；使用角色独审已测的凳子定位点，目标为母版 635×1175。

| 实际输入 | 采用点 | 结果 |
|---|---|---|
| v1（d69a90…325） | 双凳脚 | 0°、scale 0.688733，被 `[0.8,1.25]` 拒绝 |
| v2（43ef43…6e3） | 双凳脚 | 0°、scale 0.688733，同样拒绝 |
| v1 / v2 | 已有凳面角＋右凳脚 | 约 +0.116° / -0.097°、scale 约 0.68990 / 0.69013，同样拒绝 |

错误原文包含“缩放 0.69，超出范围，图和母版差太多”。这是把**像素密度转换**与**剩余人物尺寸差异**混为一个阈值；不是两图身份/姿态因此已判不合格。

最小可采用方案是先统一分辨率：对原件及其锚点使用相同等比缩放 `0.6887328884088874`，输出 635×1175 母版画布。探针在 OffscreenCanvas 实际做此操作后，两图均能由未改动的新 `loadFlip` 加载并 `flipMaps` 输出 635×1175：剩余配准均 `scale=1, deg=0`，v1 平移 (-1,+12)，v2 (-1,+9)。没有局部人物修改，也没有导出可被误当正式素材的规范化 PNG；此为加载/坐标诊断，灰底抠图和视觉质量另验。后续生产若先规范化，三张图须共享同一转换，或在规范化/抠图后重新生成 `_n/_m`，不能混用原尺寸 maps。

若希望直接读原件，建议 frame 接口显式给 `sourceSize:[922,1706]` 和 `nominalScale:0.6887328884088874`。真实对齐矩阵仍用锚点解得的总 `s`，形变限制改测 `s/nominalScale`；同时校验图片实际尺寸与 sourceSize、裁切/纵横比契约。此例剩余尺度接近 1。**不要只把全局下限降到 0.6**，也不要对任意裁切图自动假定画幅面积比就是正常缩放。

本轮不把其他作者已配准的诊断 PNG 视为正式接入输入；正式规范化图需另有来源、变换和哈希记录。

## 2. 两处校验遗漏实证

- `span([0,50])`：外层 length=2 且 `.flat().every(Number.isFinite)` 成立，但这不是两个二维点。`Math.hypot(...)` 为 NaN，`NaN < 40` 为 false。target 或 frame 使用此值均被加载接受，矩阵非有限，Canvas 没抛异常。最小更正：要求外层数组恰两个元素、每个元素为恰两个有限数的数组，并用 `Number.isFinite(distance) && distance >= 40` 判定。
- `timelineFrames:[[0,0.5]]`、至少两帧时：索引范围检查通过，`frameAt` 返回 0.5，`flipMaps` 才报 `Cannot read properties of undefined (reading 'alb')`。最小更正：增加 `Number.isInteger(i)`。

未扩展为重构或完整输入模糊测试。

## 3. 可关闭的旧时序项

用最新计划整数曝光表，在 `n/24` 的全部 72 点采样：F14=key3，F15/F16=key4；A/B 依次占 F27–29、30–32、33–35、36–38、39–41、42–44。key10 从 F45、key11 从 F54、key12 从 F63 开始。旧小数舍入和没有显式 A/B 循环的问题可关闭。这里只验证 key 索引，探针复用了同一合法图片作为多个索引输入；没有冒充 12 张新图的实际表演，也没有试听。

## 4. 缺 manifest 仍回旧片；清单不是运行凭证

新 `loadFlip` 的图坏/manifest非404错误会抛出，这一修正成立。但 S18 仍调用 `{optional:true}`：manifest 404 实测返回 null，进入旧画法；缺 manifest 的缓存 null 也不会在同一实例中重新加载。冻结时正式 `assets/flips/x18_laugh.flip.json` 不存在。

新 `tools/flip_manifest.py` 是静态清单计算器，不调用浏览器 loader，也不核上述尺度限制。额外隔离探针 `manifest_fixture/` 放入这两张实际原件和相同凳脚点，工具仍以 exit 0 输出 `mode:"flipbook"`、scale 0.6887，尽管实际 loader 刚拒绝它们。证据 `manifest_tool_results.json`。

正式审核须要求 manifest 成功响应，并绑定**实际渲染**的 mode、所用 JSON/图片哈希、每输出帧 key ID 和加载错误记录。清单可以辅佐核对，不能单凭其 `mode` 字段判定 S18 运行的是新片。没有 manifest 时应由审核入口显式失败；当前生产 legacy 行为可以另留，但不得交成关键帧成功。

结论范围：原件加载阻断和最小解除途径已实证；整数采样已修。角色一致性、捂嘴动作、灯光、完整 72 帧和正常速度观感仍待正式图与真实成片，不能把一拍三自动判为自然动作。
