# S01 奶奶绑骨样板：实际六秒片独立动作审查

结论：**可保留为连续网格驱动的技术样板，需有限修订；不能当作完整剥豆表演或用户观感已解决。** 本轮停止重复制作整套 g01 rig，仅审查 Opus 现成数据和实际交付片，给局部坐标/区域建议。没有修改仓库、生成形象、重渲动画或恢复 S31 WIP。

## 主要发现

### 1. 连续驱动成立，但动作内容仍是持豆姿势的小幅往复

实际帧 F0–143 的头、肩和双手位置连续变化，没有 A/B 整图硬切；两手始终保留原图接触：画面右侧的近手托同一开口豆荚，画面左侧的远手捏同一颗已取出的圆豆。豆荚内可见豆粒也始终留在原处。未演到捏开/取出一颗/释放入盆/换荚的状态转移。

`test_anim.js:8–15` 对近、远手臂分别设置周期旋转；没有手指骨、豆粒独立道具、释放或换荚事件。它足以证实非刚体的连续网格动作，**不足以支持注释所称“每 1.2 秒剥一颗”**。最小后续应先明确“持豆小动作”的演示标签；正式剥豆需补至少一个可读的手指开合和独立豆粒释放事件，并处理被覆盖的像素。

### 2. 盆区域误固定了绿镯和近前臂，实际片中镯子被拉变形

现有 `g01_beans.rig.json` 的 bowl region 上边经过 `[300,662] → [470,640]`，超过可见盆边，进入近腕镯底和前臂下缘。注点证据见 `rig_arm_bowl_detail.png`。

直接调用冻结的 `warp.bind()` 与 `boneMatrices()`，配合原 `test_anim.grandmaBeans(f/24)` 采样 144 帧，得到：

| 原图网格顶点 | 实际权重/运动 |
|---|---|
| `[390,660]`、`[400,650]`（绿镯下缘） | 100% `bowl`，位移为 0 |
| `[450,650]`、`[460,660]`（近前臂下缘） | 100% `bowl`，位移为 0 |
| `[400,610]`（腕上方） | 多骨混合，最大移动约 16.64 原图像素 |

这些是**源码网格数值**，不是从压缩视频反推的光流。实际片 `wrist_bangle_actual_frames.png` 的 F7、F22 可见镯子的上部随腕走、下沿滞留，形状伸缩；因此不是仅凭源码提出的假想风险。

最小修订：把 bowl region 收紧到可见盆体/盆沿，避开镯和前臂；镯作为近侧腕上的刚性部件随近前臂走。盆在手之后，不应以扩大固定区域来“锁住”遮挡它的手。修订后复查极值帧再推广。

### 3. 远臂骨点落在错误解剖位置，应先局部重标

现有远肘 `[300,510]` 落在袖口/上臂附近；远腕 `[190,480]` 已落在手内。实际弯肘区域在约 `[225,596]`，前臂与手相接的腕部约 `[166,525]`。这些是源图中的关节中心估计，不是可见骨骼测量；可在各 ±8–10 px 范围内复核。近腕现 `[400,640]` 偏向镯下沿，可先试约 `[394,616]`。

只读候选在 `g01_coordinate_suggestions.json`；它不是完整替代 rig，也未应用、未用它重渲。远肩/骨盆/膝盖受衣服与盆遮挡，本轮不冒充精确可见关节点，不新增隐蔽关节的硬钉点。

### 4. 原始源皮已有盆后沿透明缺边，不能归因成新网格撕裂

片中盆后沿上方有短黑线/断续边。把原 PNG alpha 合成到洋红底后，同样缺边已存在，见 `source_alpha_bowl_magenta.png`。本轮不会把它误报成动画引擎新裂缝；但进入正式背景前仍需修原 alpha/补原盆边，而不是用骨权重隐藏。手、豆荚、盆之间被挡住的底图没有可用补洞：更大幅度的掰手、抬盆会露出缺失区域，不能直接承诺现单图支持。

## 接口和约束边界

- 本轮新 `warp.js:78–79` **确已消费 `rig.pins`**；早期“pins 未实现”的观察不能套当前版本。此 g01 的 `pins:[]`、`layers:[]` 为空，腿/凳/盆靠 regions 和未运动的父根骨保持，而非 IK 接触约束。`warp.js:76–105` 的 regions 限定权重并跳过平滑，`119–127` 为父子前向变换。
- near 是解剖左臂（画面右侧大袖、绿镯）；far 是解剖右臂（画面左侧抬起的捏豆手）。镯腕别在此片保留。近手与豆荚是一组持握接触；远手与单颗豆是另一组；盆和盆内豆在膝上静止，不能全局绑成一个道具。
- 脚、凳子及下半身在抽查全身帧保持，没有看到新的明显滑脚；这不验证其隐藏髋膝骨点，也不证明站起/走路可用。
- 此片对应 `test_anim.js` 不传 `__blink`；新 `acts.js` 虽传眨眼曲线，不能借此宣称已交片眨眼。脸部完整逐帧结论见独立 `../g01_face/report.md`（由 character_audit 出具）。
- `layers/keepUnder/exclusive` 当前 g01 均未使用，本轮片不能验证这些功能。需拆手/指/道具时，底图补洞与前后遮挡仍是实际依赖；不能把 `keepUnder` 等同已补出隐藏手指。

## 可直接交 Opus 的最小顺序

1. 修远肘/腕、收紧 bowl region、将镯保护为近腕刚体；用同六秒动作先核极值，避免改动作和改数据混为一处。
2. 给演示加真实眨眼曲线后另交实际片；是否自然由实片判断。
3. 把“剥豆”拆成最少可读动作事件再制作，不把现有往复摆动声称完整劳动过程。先保留已有效的形象和连续驱动，不扩大成全片渲染。
