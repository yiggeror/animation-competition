# S01 小满绑骨数据独审

**结论：当前 JSON 可交 Opus 作限定范围的 S01 静态试接；不是动作或蒙皮质量通过。** 本轮按已冻结 SHA256 `1431fb65b98a19762cfb9e25c1dbb39d62bdc355ff46cf02f356f052859ad350` 收口，不再等待新渲染或扩大制作。仍有一处明确限制：head region 含左辫下可见黄衣片，因此本候选先保持 head 不动；启动头部动作前需修该范围或以实际画面证明没有误带肩衣。其他边缘风险留首轮实渲验证。

## 身份与结构

- 受审文件：`/tmp/laidian-s01-rigs/x01_prone_phone.rig.json`；独审冻结副本 `rig_final_reviewed.json`，上述 hash。
- 原件：`/workspace/animation-competition/assets/chars/x01_prone_phone.png`，1536×1024 RGBA，SHA256 `9c99009187235b2e5ed2fccea85275957494c79dde56d95c55ff7e696332ad2a`。灰色 RGB 背景的 alpha 为 0，未修改图片。
- 17 根骨，无重复名、缺父、环、越界或零长；父先子后，符合当前单遍矩阵计算，低于 shader 32 骨上限。8 个 regions 的引用有效、多边形无自交或越界；8 个对象 pins 引用 root；两 eyes 参数有限且中心在可见眼内。
- `layers=[]`。没有使用已否定的抽层诊断作为生产输入，不存在本轮“层多边形带走另一手”的抽图操作；regions 的首个匹配仍决定权重归属，需按其实际边界核查。
- 肘→腕→手、膝→踝→脚链的相邻端点完全相接。肩相对 spine、髋相对 root 是有意的分支偏移，不是必须等于父骨 tail 的串联关节；当前消费者按绑定姿态坐标支持这类偏移。

## 原图能确认与不能确认的部分

near 对应前景手臂及较直的前景小腿；far 对应后景手臂及向左倾的小腿，命名与原图遮挡关系一致。报告采用这个可见约定，不额外证明被遮住的解剖左右。

肩被袖子覆盖，髋被裙子覆盖，远膝被近腿遮挡，均只能作为二维代理。作者已标估计和误差范围，不能作准确骨骼透视重建。两只鞋在空中，不应当作接地脚底。

手机背面朝镜头、屏幕侧拇指不可辨。当前没有 thumb 骨、没有补猜被遮住的指节，也没有把上沿/角部露指强称拇指。这一点通过。hand_near/far 仅保留测量链；可见两掌指及手机整体共用 phone region，**没有独立按屏、握放或手指表演能力**。

phone 骨父为 root，与双掌共用一个单骨权重范围，可在同一刚性变换下保持原图内部握机关系。其范围实看未误带头脸或另一个身体大块。root 与 phone 必须按交付说明不伸缩、先保持静态；把 phone 改挂到会伸缩的 spine/手臂会重新引入非刚体风险。腕外侧与前臂属于不同权重区域，二者动态边界不是由这份 JSON 自动闭环求解。

## regions 与 pins 的实际核查

独立按 regions 首个匹配顺序栅格化回原图，检查了全部 8 个有效范围；诊断图为 `region_00_effective.png` 至 `region_07_effective.png`。这些只是权重归属的可见诊断，不是引擎已经抽层或变形的结果。

作者已按首轮意见收回明显的右辫底衣片、颈侧白领、近臂袖/发边及交叉小腿条，并清理了旧“只抽手机壳/由 hand 驱动像素”等与最终方案冲突的说明。

**剩余明确限制：** `region_01_effective.png` 中左辫下仍带一块黄肩衣，约原图 x927–972、y533–579；原 polygon 末段的 (972,539)、(958,563)、(940,582) 越过实际深棕发梢。它不是隐藏补图，也不是单像素线边。静态原位没有错误，但只给 head 权重后会随头一起变换。当前限定试接必须保持 head 静态，不能把“允许 ±1°”建议写成已通过范围。

其他 limb/躯干边界还可见少量轮廓条归 root/spine 兜底；约 10 px 网格会跨越 region 边界，仅靠多边形像素准确也不能保证三角片交界不拉裂。因此初次试片要放大腕、肘、膝和发梢—肩交界，不再为静态数据逐像素无限加点。

肘底 pins (1120,854)/(1336,794)、近膝下缘 (278,739)/(314,742) 均落在对应可见接地轮廓像素；另两膝代理中心及裙摆/胸腹下缘的含义在 notes 中分开。远膝 pin 所在可见像素属于遮住它的近腿，作者已明确其是固定代理，不是远膝接地的直接证据。pins 只是半径内网格权重归 root，**不是 IK，不会自动保证骨内肘膝中心、完整轮廓或腕部接触同时成立**。

## 两只眼

近眼 c=(1201,472)、远眼 c=(1291,470) 与原图可见眼位置一致；椭圆方向能覆盖主要眼白/虹膜。`eyes_source.png`、`eyes_overlay.png` 留有原图与几何对照。

这些参数只作为遮罩候选：远眼紧邻脸边，上睫线末端接近/超出椭圆边界；实际引擎另加 2 px 覆盖，必须查看半闭和全闭实帧确认旧睫线、虹膜是否残留、皮肤色是否突兀、闭眼线方向是否合适。此轮没有眨眼动画通过结论，也没有证明表情自然。
